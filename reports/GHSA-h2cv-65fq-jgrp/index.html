Command Injection in yq via -o=shell -r

Command Injection CVSS 7.8 HIGH CWE-78: OS Command Injection mikefarah/yq ≤ v4.54.1

GHSA-h2cv-65fq-jgrp · CVE assignment pending (MITRE CNA-LR)

Summary

The -o=shell output format in yq is designed to emit shell-escaped values that can be safely eval'd. However, when combined with the -r (raw output) flag, the shell escaping is bypassed and user-controlled input is passed directly to the shell without sanitization.

Affected versions: all versions up to and including v4.54.1. The vulnerability exists in the shellWriter function which processes the -o=shell format.

Impact

  • Arbitrary command execution — an attacker who controls the input YAML/JSON (e.g., via a config file, CI/CD pipeline variable, or API response processed by yq) can execute arbitrary shell commands with the privileges of the yq process.
  • Attack vector: local/remote — any context where yq processes untrusted input with -o=shell -r flags.
  • Real-world scenarios: CI/CD pipelines parsing attacker-controlled YAML, configuration management tools, Kubernetes manifest processing, API response transformation.

Root Cause

The shellWriter in pkg/yqlib/shell_writer.go applies shell escaping unless the -r flag is present. When -r is used, the raw string is written directly without escaping:

// pkg/yqlib/shell_writer.go (simplified)
func (w *shellWriter) writeString(s string) {
    if w.rawOutput {
        // RAW OUTPUT — NO ESCAPING
        w.writer.WriteString(s)
        return
    }
    // Normal path: shell escape the string
    w.writer.WriteString(shellEscape(s))
}

The documentation and flag interaction imply -r only removes quotes from output, but in practice it disables the shell escaping entirely for -o=shell.

Proof of Concept

Create a malicious YAML file:

# evil.yaml
payload: "$(id > /tmp/pwned)"

Process it with yq using the vulnerable flags:

yq -o=shell -r '.payload' evil.yaml
# Output: $(id > /tmp/pwned)
# When eval'd: executes 'id > /tmp/pwned'

If the output is used in a shell context (e.g., eval $(yq -o=shell -r ...) or sourced), the command executes immediately. Even without explicit eval, the output is intended to be shell-safe — the -r flag breaks that contract.

Fix

  • Shell escaping is now applied regardless of the -r flag when -o=shell is used — the -r flag only controls quoting, not escaping.
  • Updated documentation to clarify that -o=shell output is always shell-escaped.
// pkg/yqlib/shell_writer.go — after fix
func (w *shellWriter) writeString(s string) {
    // Always escape for shell output format
    escaped := shellEscape(s)
    if w.rawOutput {
        // rawOutput only controls quoting, not escaping
        w.writer.WriteString(escaped)
        return
    }
    w.writer.WriteString(escaped)
}

Fixed in yq v4.54.2 (2026-10-23). Advisory published 2026-10-23; CVE assignment pending via MITRE CNA-LR.
